# 🟢 Исправление статусов ложно закрытых Penny Stocks

## Что было сделано
Была выявлена проблема, из-за которой система ошибочно переводила некоторые Penny Stocks в статус `RESOLVED` (в том числе рынок Guangzhou 2456480 и ещё 6 рынков, которые показывались в дашборде как "Выигранные"). Причина заключалась в некорректном извлечении цен из API Polymarket для рынков, где одна из сторон (например, NO) доходила до 99¢ — система могла посчитать такой рынок завершённым, хотя фактически он был ещё `closed: false` (ACTIVE).

Для решения этой проблемы был написан скрипт миграции:
- **Создан скрипт:** `scripts/fix_penny_stocks_status.py`
- **Логика:** Скрипт сканирует всю таблицу `penny_stocks_monitoring` для рынков в статусе `RESOLVED`. Для каждого рынка он делает актуальный запрос к Gamma API Polymarket. Если API возвращает `closed: false`, то статус рынка в БД принудительно возвращается в `ACTIVE`, а ошибочно зафиксированные исходы сбрасываются.
- **Восстановление покупок:** Для рынков, которые уже были "разрешены" и попали в `penny_virtual_trades_history`, скрипт восстанавливает из истории `virtual_bought_price`, `virtual_bought_at` и `bet_size_usdc` обратно в таблицу мониторинга, а саму "фейковую" запись о завершении сделки удаляет.

## Что происходит сейчас
Скрипт загружен на сервер и в данный момент выполняет массовую проверку всех разрешённых Penny Stocks (более 500 рынков). Из-за ограничений частоты запросов к API это может занять около 3-5 минут. По завершении проверки все неверно разрешённые рынки (включая указанные вами 6 штук и Guangzhou) исчезнут из списка разрешённых и вернутся в активный портфель (с правильными ценами входа).

> [!NOTE]
> Скрипт выполняется в фоне. Как только он завершит работу (в ближайшие несколько минут), вы увидите актуальные данные в дашборде. Дополнительных действий не требуется!
